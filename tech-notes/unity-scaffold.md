# Unity 2022.3 项目脚手架：搭建与踩坑记录

《古代卡牌生存》的项目从零搭建到现在能打出 APK，中间踩了不少坑。这篇把脚手架阶段值得记的东西留下来：版本选择、依赖注入框架安装、目录组织、打包和上架前的合规。

## 版本选择：2022.3 LTS

用的是 **Unity 2022.3.55**。选择理由很简单：

- LTS 版本维护周期长，不会像 Tech Stream 一样频繁换 API。
- VContainer、R3 这些社区库对 2022.3 的兼容性验证最充分。
- 网上踩坑记录最多，遇到问题搜得到。

没有特殊需求不要追新版本，游戏项目最怕的是"升级一时爽，兼容火葬场"。

## 依赖注入与响应式：VContainer + R3

两个包都通过 UPM 安装：

- **VContainer**：官方支持 git URL 直接装，也可以用 OpenUPM。
- **R3**：可以在 OpenUPM 搜到，或者直接加 git URL 依赖。

安装完第一件事是验证编辑器里能打开 VContainer 的菜单（Window > VContainer），确认版本号正确。这一步别看日志，直接肉眼确认，省得后面代码写了一半才发现根本没装上。

## 目录组织：按 Feature 而不是按类型

早期容易犯的错是把脚本按 `Scripts/UI`、`Scripts/Logic` 分，结果改一个功能要跨三个目录。现在改成**按功能模块组织**：

```
Assets/Scripts/
  Battle/       # 战斗逻辑
  Cards/        # 卡牌数据与生成
  UI/           # 界面
  Core/         # DI 容器、启动流程、全局服务
  Effects/      # 水墨特效相关
```

每个模块内部自包含：数据、逻辑、UI 各自放小目录。新功能进来先建模块，不往公共目录塞。

## APK 打包与踩坑

打包 Android 的注意点：

1. **IL2CPP 首次编译很慢**，第一次打包等个十几分钟很正常，别以为卡死了。
2. **AndroidManifest**：上架前必须核对包名、权限声明。游戏用不到太多权限就少声明，权限越多审核越慢。
3. **隐私政策**：TapTap 上架要求提供隐私政策页。现在站点里的 `privacy-policy.html` 就是这个用途，游戏内也要有对应入口。

## GitHub Release 分发

内测包走 GitHub Release：打 tag 触发，Release 里挂 APK 附件，玩家从 Release 页面下载。比 QQ 群发文件多了版本管理和下载统计，群文件只用来做通知渠道。

## 留档的小经验

- 每次"装完包就报错"先查版本兼容表，R3 对 Unity 版本有要求。
- 打包配置（签名、keystore）第一时间提交到仓库（keystore 本身别提交，放本机）。
- 项目里用到的包版本，在 README 里记一行，半年后回来看不靠记忆。
